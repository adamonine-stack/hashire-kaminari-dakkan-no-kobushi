# 真ボス撃破後の真エンディング軽量化

## 対象と変更

真エンディングの導入は `Player.tscn` を3体生成し、各キャラクターの戦闘用テクスチャ一式をロードしていた。通常の戦闘シーンからの遷移でも、新シーンのロード開始時には旧シーンが残っていた。

- 戦闘キャラクターを、必要な立ち絵とセイヤの歩行6フレームだけを持つ軽量ノードへ変更。正式素材のピクセル、表示位置・倍率・フレーム時間・頭部補正を抽出して保持する。
- 元のキャラクターテクスチャ展開量: 302,194,688 bytes。専用キャスト: 3,825,664 bytes（約98.7%減）。これはRGBA換算の画像量であり、アプリ全体の使用メモリではない。
- 真ボス戦の入力・AI・キャラクター処理を止め、旧シーンを解放して2フレーム待ってからエンディングをロードする。
- CGは表示上限1280pxでインポートする（元画像1672×941は保存）。前の画像を解放してから次をロードし、カード・エンドロール前にも解放する。
- スイッチ場面前に人物画像を解放。爆発のGPU粒子130個、煙シェーダー、無限Tweenを、23個の小さな図形による演出へ置換。夜明け前に演出ノードを解放する。
- 使用終了した効果音のストリームを解放し、エンドロール前には全SEを解放する。
- 真ボス撃破後はTrueEndingの再開地点を保存。再起動後のCONTINUEでボス戦を繰り返さず再生できる。達成記録を保存できた時点でこのチェックポイントだけを削除する。

セリフ7行、12場面の順序、主題歌の最後までの再生、既存の達成保存項目を維持する。

## 検証

- `TRUE_ENDING_CHECK failures=[]`: 場面順序、セリフ、画像メモリ上限、人物・CG・SE・爆発ノードの解放、保存項目の維持。
- `TRUE_ENDING_CHECKPOINT_CHECK failures=[]`: CONTINUEからの再開、他のセーブの保護。
- `TRUE_SEIYA_COMBAT_CHECK failures=[]`: 実際の攻撃命中による真ボスKOからエンディングへの遷移。
- 通常Stage 8の7分岐と既存チェックポイントも成功。
- 844×390の描画確認で敗北会話、爆発、夜明け、エンドロールを確認。Web書き出し後のPCKでも真エンディングチェックが成功。
- 入力停止修正のガード回復、タッチ入力、ステージ1の回帰チェックを再確認。

実機iPhoneの手動確認ではない。公開Web版の通常速度での完走確認は、デプロイ後の記録を参照する。
