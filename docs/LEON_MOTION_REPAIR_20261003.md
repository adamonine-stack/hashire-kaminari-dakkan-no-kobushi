# 第8ステージ レオン・クロウのモーション修正

現行 `leon_v1` の元画像は、横幅・行高が不均等な40ポーズの画像だった。6×6の36セルとして等分した結果、攻撃や被ダメージで頭・胴・脚がセル境界に切られていた。さらに旧damageは紫の攻撃原画、旧throwは回転キック原画を参照していた。Sprite.scaleが一定であるだけの検査では、この欠けと誤割り当てを検出できなかった。

## 実装

- 元画像の全身領域を計測して `leon_v2` に再配置。元画像の復元部分には一つの倍率を適用し、待機時の旧表示高296pxと188cm設定を維持する。512×448の共通セルと404pxの接地基準を使い、動作別の実行時拡大縮小をしない。
- 通常被弾・吹き飛び・転倒・起き上がりを、元画像に残っていた正しい全身原画へ割り当て直す。キックへのジャンプ原画、落下への蹴り原画、投げへの必殺技原画の流用を修正。
- しゃがみパンチの予備／打撃、投げの掴み／保持／放し、回転キックの計6原画をbuilt-in image_genで再制作。正式な黒髪、黒革ジャケット・パンツ・手袋・編み上げブーツ、紫の背中の翼を参照する。生成素材と入力・条件は `art_sources/leon_motion_v2/` に保存。
- 立ちガードとしゃがみガードが混在していた割り当てを分離。投げの各状態で汎用throwへ上書きされないよう、レオンだけ状態別原画を選ぶ。
- 突進・回転キックの実行中に汎用specialへ上書きされる経路を修正。毎更新で先頭フレームへ戻されていた再生進行も、レオンの特殊技だけ維持する。ボス三技を予備・打撃・戻りに分け、通常攻撃も命中時刻に打撃原画を同期する。
- 三人の必殺技を受ける専用原画も共通セル・接地基準へ揃える。各反応系列の空中と転倒には同じ倍率を使い、着地で体格を変えない。既存の壁反応、270度回転、頭からの着地と技別IDは維持。
- HP、ダメージ、ヒットボックス、移動速度、各技の時間、AI、ゲージ、ステージ・エンディング、他キャラクターの原画を維持する。

## 検証

`leon_motion_integrity_check.gd` は実Battle.tscnを第8ステージに設定し、全使用165フレームを検査する。使用する41種類の原画を左右両方向に表示し、透明余白、全身の画面内表示、足・転倒の接地位置、表示倍率と原点、体格を確認する。さらに左右とも実接触で通常被弾・通常キック・ガード・投げの全状態・ボス三技を確認し、中間打撃原画が実際に再生されることを検査する。

レオンに限定した `leon_received_{akky,gou,seiya}_check.gd` で、三人の必殺技を受ける命中・空中・壁／回転／頭からの着地・転倒・ガード・KOを実描画する。共通の各技回帰でも全敵への既存動作を確認する。

`leon_web_qa.tscn` は同じ検証を通常Nodeに生成したWeb用シーン。新しいブラウザー状態の一度限りの `user://qa/leon_motion.flag` を消費して起動し、配信PCK/WASMを変更せずに検査する。通常のセーブやNew Gameはこのフラグを作らない。撮影完了をブラウザーから受け取るまで検証を止め、画像と確認した動作がずれないようにする。CIにも同じシーンを登録。

証拠は独立作業ツリーの `evidence/leon_runtime/`、`evidence/leon_received_*/`、各最終ログ、`evidence/web/leon_*/` に保存する。制御された実描画と戦闘検査であり、実機スマートフォンでの手動プレイや全ステージ手動通しプレイとは区別する。

再構築手順: `python tools/audit_leon_source.py` → `python tools/build_leon_motion_v2.py` → `python tools/build_leon_web_qa.py`。元の `leon_v1` と他敵の原画は保持する。
