## 2. 問題を起こしたResourceの参照経路

| ステージ | 敵定義 | 実際に参照していたAtlas |
|---|---|---|
| 5 | `godot/data/enemies/enemy_02_speed.tres` | `assets/characters/enemy05/animations/shadow_boxer_v1/motion_atlas.tres` と同フォルダーのPNG |
| 6 | `godot/data/enemies/enemy_06_combo.tres` | `assets/characters/enemy06/animations/rio_garcia_v1/motion_atlas.tres` と同フォルダーのPNG |

第5の敵定義ファイル名には `enemy_02` とありますが、描画元は `enemy05` フォルダーのShadow Boxer Atlasです。フォルダー名だけを見て古い `enemy02/sprite_sheet.png` を修正しても、実際の崩れは解消しません。

描画処理は `godot/scripts/characters/character_visual_controller.gd` の `_build_authored_motion_atlas()` です。旧処理はフレーム番号から次の式で一律にRegionを作っていました。番号は0始まりです。

```text
x = (frame_number % columns) × cell_width
y = floor(frame_number / columns) × cell_height
width = cell_width
height = cell_height
```

SpriteFrames共有による他キャラクターとの混線や、Z順で靴が重なっていたことが原因ではありません。**ひとつのAtlasTextureのRegionに、別段の靴と本来の身体の一部が同時に入っていました。**

## 3. 画像と分割定義の不一致

| 項目 | Shadow Boxer | Rio Garcia |
|---|---:|---:|
| 元PNGサイズ | 1230×1278px | 1261×1247px |
| 旧セルサイズ | 153×159px | 157×155px |
| 旧列数 | 8 | 8 |
| 旧参照番号の最大値 | 63 | 63 |
| 実際のポーズ配置 | 高さが不均等な7段 | 高さが不均等な7段。タックル段は7ポーズ |

旧定義の「8段目」は、画像の8番目のモーション段ではありません。画像の下側にある実際の7段目を途中から切っていました。Region自体がPNGの範囲内に収まる例があるため、Godotの読み込みエラーがなくてもキャラクターは崩れます。

代表例（`Rect(x, y, width, height)`、座標は元PNG上）:

| 箇所 | 旧Region | 修正後の完全な元ポーズ範囲 | ずれの結果 |
|---|---|---|---|
| Rio Idle、番号0 | `(0,0,157,155)` | `(17,11,132,171)` | 身体の下端はy=182まであるのにy=155で切るため、下側27px分が範囲外 |
| Rio Walk、番号8 | `(0,155,157,155)` | `(14,195,136,148)` | y=155付近の前段の足も拾い、歩行ポーズの下端y=343をy=310で切る |
| Shadow Hit、番号48 | `(0,954,153,159)` | `(31,1003,113,181)` | y=954付近の前段の足を拾い、本来の被弾姿勢の下端y=1184まで届かない |
| Shadow 旧KO、番号56 | `(0,1113,153,159)` | KO先頭は実際の倒れ姿勢、番号51 `(468,1095,148,89)` へ変更 | 旧番号56は最終段の立ち姿の脚付近から切り出すため、上半身が消える |

数pxのoffset調整では解決できません。切り出す時点で頭や足が失われ、違う絵の断片が入っているためです。

## 4. どのモーション参照を直したか

共通する代表的な修正は次のとおりです。番号は新しい測定ポーズ一覧に対する0始まりの番号です。

| モーション | 修正前 | 修正後 |
|---|---|---|
| Down / KO | `[56,57,58,59]` | `[51,52]`：倒れる→寝倒れ |
| GetUp / StandUp | `[59,60,61,62,63]` | `[52,53,54,0]`：寝倒れ→起きる→Idle |
| KnockDown | `[50,52,54,56]` | `[49,50,51,52]` |
| Land | `[55,56]` | `[40,0]`：低い姿勢→Idle |
| Thrown | `[51,53,55]` | `[49,50,51,52]`：勝利姿勢の混入を除去 |
| Victory | `[60,61,62,63]` | `[55]`：実際の勝利ポーズ |
| Shadow Crouch系 | `[20,21,22,23]` | `[40]`：実際のしゃがみ姿勢 |
| Rio Crouch系 | `[18,19,20,21]` | `[40,45]`：実際の低い姿勢 |

Idle/Walk/Dash/攻撃/必殺等も、同じ番号であってもSource Regionをすべて測り直しています。番号を直した動作だけが改善したわけではありません。一方、既存のキャラクターにない新しい攻撃モーションを描き足す作業は行っていません。

## 5. 足元と大きさをどう安定させたか

各キャラクターに56個の `frame_regions`、`frame_offsets` を持たせ、完全な元ポーズを透明な320×256pxセルへ配置します。実行時のAtlasは8列×7段、2560×1792pxです。元PNGは変更していません。

立ち姿の足元を共通セル内の基準へ揃え、IdleからSpriteの基準位置を計算します。offsetをモーションごとに振ったり、毎フレームscaleを変えたりする処理はありません。Shadowの最終反応段は元絵の描画倍率が大きかったため、その段全体を共通倍率0.832402で補正しています。身体高さの基準もShadowは132→149px、Rioは130→169pxに修正しました。

`centered`、Spriteのoffset、position、scale、Z順、独立したSpriteFramesを確認し、床Colliderとキャラクター本体の立ち位置を維持しました。足を床やUIで隠す対応はしていません。

実装箇所:

- `character_visual_controller.gd` の `_build_measured_motion_atlas()`：完全なポーズの配置、範囲検証、固定Region生成
- `fighter_motion_atlas.gd`：測定Region・配置offset・段の倍率を保持
- Shadow/Rioの `motion_atlas.tres`：各ポーズの正しい座標と各モーションの参照番号
- `enemy_02_speed.tres` / `enemy_06_combo.tres`：完全な身体高さによる表示サイズ基準

## 6. 修正後の検証範囲

第5は69登録Clip・48種類の重複しない実描画フレーム、第6は76登録Clip・56種類の実描画フレームを確認しました。Idle、Walk、Dash、Jump、Punch、Kick、必殺、Guard、Crouch、Hit、Down、GetUp、KO、投げ関連、Victoryを含みます。同じAtlas Regionを使う別名Clipは共通フレームとして照合しています。

第5～8は自動入力と実状態遷移によるIdle/Walk/Jump/Attack/Hit/KOも確認しました。第1～4は回帰確認済みです。確認方法は非headless GodotでBattle.tscnを描画し、描画完了後のViewportを保存して目視確認するものです。手動対戦を実施したという報告ではありません。

修正後の全身表示・セル境界・一定のscale/pivot・範囲外参照を検証するテストも成功しています。今回確認した切断・頭上の靴・隣ポーズの混入は、修正後の実描画では検出されませんでした。
